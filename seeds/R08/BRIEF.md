# R08: resumable staged export

Extend the independent prepared v1 exporter using Python 3.11+ standard library only. Edit only `main.py`; no network/subprocesses. CLI:
`python main.py REQUEST STATE OUTPUT [--through plan|export|verify] [--fail-before-publish]`.
Default through=verify. Flags may appear in either order, each at most once. The failure seam is allowed only with through=verify.

Request is UTF-8 JSON with exactly schema_version, order_id, steps, items. Version is integer 1 or 2, never boolean. order_id is a nonempty string. steps is exactly ["plan","export","verify"]. items is an array of objects with exactly id and text: id is unique/nonempty string, text is any string. Preserve strings exactly; sort items by Python Unicode id. Reject duplicate object keys, nonfinite numbers, wrong types/fields and malformed UTF-8/JSON before changing anything.

Canonical JSON bytes throughout this task mean `json.dumps(value, ensure_ascii=True, sort_keys=True, separators=(",", ":")).encode("utf-8")`, with NO newline. The v1 result remains exactly {"schema_version":1,"order_id":ID,"items":SORTED_ITEMS}. Version 2 keeps these fields with schema_version=2 and adds exactly "manifest":{"sha256":DIGEST}; DIGEST is the lowercase SHA-256 of canonical result bytes WITHOUT manifest. Both versions publish canonical bytes.

STATE is a canonical JSON journal with exactly request_sha256, completed, counts. request_sha256 hashes the ORIGINAL REQUEST bytes. completed is a prefix of ["plan","export","verify"]. counts has exactly those stage names, 1 for completed stages and 0 otherwise. A missing state starts with no completed stages. Existing state must match the raw request SHA and this exact schema/invariant; otherwise exit 2 and preserve all artifacts. A missing state with an existing STATE+".draft" is a conflict; preserve it.

Run missing stages in order up to through: plan records completion; export writes the complete canonical result to STATE+".draft", then records completion; verify validates that draft equals the expected canonical result, atomically replaces OUTPUT with it, then records completion. OUTPUT must remain unchanged (or absent) until verify. Persist each completed stage; each stage runs at most once according to counts, even across process restarts. Retain the draft after verify. Calling through=plan/export after later stages is a no-op. Completed verify must not rewrite output; require the existing output to equal the expected result, else report conflict without changes. An export-completed state requires the original matching draft on every resume; reject missing/corrupt draft before changing anything.

The --fail-before-publish seam runs plan/export if necessary, then exits 2 immediately BEFORE publishing/verifying, with nonempty stderr; verify remains incomplete and output stays unchanged. A normal retry resumes and finishes without recounting plan/export. The seam is a no-op after verify is already complete. Full machine crash/power-loss recovery and concurrent processes are outside this task.

Input, state, output and draft paths must be distinct; reject aliases (including REQUEST=OUTPUT, STATE=OUTPUT and OUTPUT=draft). Parent directories already exist; missing/unreadable input, directories used as files, invalid flags/arity and other handled errors exit 2 with empty stdout and nonempty stderr. Except for completed plan/export at the explicit failure seam, errors preserve existing request/state/draft/output bytes. Schema/path/state validation and draft verification must precede any changes. Success exits 0 with empty stdout/stderr. Use unique temporary files for atomic replacement, clean them on handled success/error, modify no unrelated files.
